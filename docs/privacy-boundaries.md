# Privacy Boundaries

This public worktree is built around synthetic data. Real private career records do not belong in the public example dataset or generated public artifacts.

## Allowed Public Content

- generic engine code
- public schemas and templates
- default configuration that does not expose private identifiers
- fully synthetic datasets
- generated outputs from fully synthetic datasets
- documentation that describes patterns without exposing private source material

## Not Allowed

- real contact details
- real application materials
- real private job notes
- real private resumes or cover letters
- private configuration
- private generated outputs
- private local machine paths
- private repository names or internal audit details

## Synthetic Data Rule

Synthetic data should be fictional in substance, not just renamed. The Andy Barks example uses fictional employers, dates, projects, accomplishments, and evidence to avoid paraphrasing a real career model.

## Later Safeguards

Automated privacy and CI safeguards are planned for a later migration phase. Until those are complete, public review should treat every new data or generated-output file as sensitive until checked.
